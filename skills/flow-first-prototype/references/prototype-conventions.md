# 原型代码约定

阶段 4 开始前读。目标是让原型**能被当成任务流程来评审**，而不是一堆互不相干的截图。只做方案或信息架构时不需要创建原型代码。

## 1. 一条流程一次生成

不要“先给你做列表页，你看看行不行，行的话再做详情页”。逐屏生成容易导致：假数据对不上、跳转是假的、状态传不过去、交棒环节丢失。至少按一条可端到端验收的 journey slice 生成；拆分时共享同一份状态和事件契约。

在选定的 journey slice 内，屏与屏之间用真实跳转串起来。

## 2. 共享 mock 状态

所有屏幕读同一份数据源，放在一个地方：

```js
const store = {
  currentRole: 'submitter',       // 当前角色，devbar 可切
  screenState: 'normal',          // normal | first | revisit | empty | loading | validating | success | error | forbidden | stale | conflict
  entry: 'list',                  // list | todo | notification | deep-link
  currentObjectId: '1024',
  orders: [ /* ... */ ],          // 业务数据，所有屏共用
  draft: { /* ... */ },
  version: 3,
  updatedAt: '2026-10-02T09:30:00+08:00',
  session: { userId, orgId, permissions: [] },
};
```

判定原则：**如果在列表里改一条数据的状态，详情页必须跟着变**。做不到就说明状态没共享，等于每屏各画各的。

## 3. devbar（L2/L3 或需要多状态评审时）

L2/L3 或需要反复评审多种状态的原型，在页面顶部或右下角挂一个可折叠的浮层控制条，至少包含以下项目。L1 单步原型如果没有有意义的角色、状态或数据规模变化，可以省略 devbar，但仍要能重置并重复演示主任务。

- **角色切换器** — 切完立刻重渲染，同一屏在不同角色下的差异要能一眼看出来
- **状态切换器** — 按当前交互面支持正常 / 首次 / 回访 / 空 / 加载 / 校验中 / 成功 / 局部错 / 全局错 / 无权限 / 过期 / 并发冲突；不适用的状态不要硬造
- **数据规模切换** — 0 条 / 1 条 / 20 条 / 2000 条
- **入口与对象切换** — 从列表、待办、通知或深链进入，并切换当前对象
- **重置** — 一键回到初始状态，方便反复演示

没有 devbar，评审时所有人只会看到理想态，等于阶段 3 白做。截图给别人看时可以收起来；它不能替代真正的入口、权限和异常路径。

## 4. 跳转与传参

- 用 hash 路由（`#/orders/1024/review`）或多文件 + query，总之**地址栏要变**，这样能直接把某一屏的链接发给别人
- 跳转时带上来源：`#/orders/1024?from=todo`，因为从待办进来和从列表进来，返回按钮和面包屑的行为不一样
- 支持直接输 URL 进入中间某屏——这是阶段 2 要求列出的入口之一，原型里要能验证
- 路由参数、共享状态和动作事件要能解释同一条流程中的前后关系；不要用隐式的全局变量掩盖对象状态迁移

## 5. 交互面的最小契约

每个页面、抽屉、弹层或内联区域都要有一个主任务和一个主 CTA，并保留当前对象、入口来源、未保存内容和返回语义。动作完成后要显示对象状态、下一步和责任人；错误要说明恢复动作和数据是否保留。连续步骤可以合并在同一交互面，避免为每个流程节点创建一张页面。

## 6. 假数据规范

- 用**真实感的中文**：项目名像真项目名，公司名像真公司名，金额有零有整
- 不要 `Lorem ipsum`、`张三/李四/王五`、`测试1/测试2`、`aaa`
- 故意塞进去几条边界数据：一个超长名称、一个金额为负、一个关联对象已删除、一个已离职的经办人
- 数据量按 devbar 的规模档位生成，2000 条那档用循环造，不要手写

## 7. 保真度

默认走**中保真**：真实布局、真实信息层级、克制的样式，不做视觉设计。

- 优先用一套简单的设计 token（间距、字号、灰阶、一个主色），不要每屏各调各的
- B 端管理端信息密度要够——不要把表格做得跟落地页一样松，那会掩盖真实的信息拥挤问题
- 明确不做的：品牌视觉、精细动效、插画。这些留给后面的视觉环节

## 8. 技术选型

- 首选**单文件 HTML**（内联 CSS + JS，CDN 引依赖），双击就能开，方便发给别人
- 屏数超过 12 或交互复杂时再上极简 SPA
- 不要引入需要构建步骤的东西，原型的价值在于打开就能看

## 9. 交付时附一份导览

原型目录下放一个 `README.md`：

- 怎么打开
- 有哪几条流程，每条流程的入口 URL
- devbar 怎么用
- 已知没做的部分（明确列出来，避免评审时反复被问同一个问题）
